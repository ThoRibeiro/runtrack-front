L'architecture

Un hexagone qui ne peut pas mentir

packages/core contient le domaine, les calculs purs et les cas d'usage. Zéro React, zéro Expo, zéro DOM, zéro dépendance. Ce n'est pas une convention : c'est vérifié à chaque build par trois gardes indépendantes, et il faut les contourner toutes les trois pour y glisser un import de plateforme.

Une règle de lint

Elle interdit nommément les imports de React, d'Expo et des modules Node depuis core. Elle échoue vite, dans l'éditeur.

Un tsconfig sans lib.dom

Ni types globaux. window, fetch et setTimeout n'existent tout simplement pas pour le compilateur.

Un test

Il parcourt l'arbre des dépendances réelles du paquet publié. C'est la seule garde que la configuration ne peut pas assouplir par accident.

Le bénéfice se voit à l'endroit où l'on ne l'attend pas : la carte a deux adaptateurs — react-native-maps sur mobile, MapLibre GL sur le web — et pas un seul Platform.OS dans un écran. Le choix se fait à la résolution du module, pas à l'exécution.

Le design system

Trois thèmes déclarés token par token

Aucune valeur de couleur ne se lit ailleurs que dans le thème — une règle de lint refuse un code hexadécimal écrit dans un écran. Les trois thèmes (clair, sombre, et un thème de course lisible en plein soleil) déclarent les mêmes clés : un composant qui marche dans l'un marche dans les trois, ou le compilateur le dit.

#2563EB l'accent — 5,17:1 sur blanc
#1D4ED8 l'état pressé, le texte sur teinte
#15264D le texte principal — 14,83:1
#53627D le texte secondaire — 6,16:1
#F3F6FB la surface alternée

5,17:1, c'est la décision. Un accent qui ne passe que 3:1 doit être doublé d'une seconde teinte pour le texte, et cette paire est une règle que personne ne retient au moment où il en a besoin. Ici une seule couleur fait les remplissages et les libellés. Le contraste n'est pas revendiqué : il est mesuré par 131 assertions qui parcourent chaque paire de chaque thème, et trois couleurs du cahier des charges ont été corrigées parce que ce test les a trouvées sous le seuil AA.

L'anneau de focus a demandé sa propre décision. Un contrôle peut être posé sur du blanc ou sur la carte d'accent : aucune teinte unique ne contraste avec les deux. Il est donc double — un trait sur un trait — et quel que soit le fond, l'un des deux se voit.

Les décisions

Six choix qui expliquent le plus de code

Chaque lot a laissé son fichier de décisions dans docs/. Voici celles qui reviennent le plus souvent quand on lit le code.

  1. EventSource est écarté

    Pas pour la raison qu'on lit d'habitude : il ne sait pas porter d'en-tête, et le flux est authentifié comme le reste. Le SSE est donc analysé à la main, avec deux transports choisis sur une capacité et non sur une plateforme — le corps de fetch en flux quand il existe, XMLHttpRequest sinon.

  2. La carte est pilotée impérativement

    Une position par seconde pendant trois heures ne provoque aucun rendu. La logique reste dans l'hexagone ; elle pousse les points vers le rendu au lieu de passer par l'état de React. Le bandeau, lui, se redessine au plus une fois par seconde, et c'est le hook qui le garantit.

  3. La tâche d'arrière-plan écrit elle-même

    Quand l'application a été tuée, personne n'écoute : la tâche écrit directement dans SQLite. C'est ce qui tient la promesse « une course ne se perd pas ». Le tampon est testé contre un vrai moteur SQLite, kill de l'application compris — pas contre une doublure.

  4. La clé d'idempotence est déduite

    Elle vient du contenu du lot, pas d'un tirage au sort. Un renvoi après une coupure réseau porte donc la même clé, et le serveur le reconnaît — sans quoi une reprise dupliquerait la course.

  5. Le jeton de partage voyage dans le chemin

    /shared/v1/{token}, et non dans un en-tête. Le lot 4 avait supposé l'inverse ; le serveur n'a jamais lu cet en-tête. La correction est écrite dans les décisions du lot 11 plutôt que passée sous silence.

  6. Le hors-ligne est une liste blanche

    Le fil déjà lu et les courses déjà ouvertes survivent à une coupure — et rien d'autre. Surtout, une requête en pause n'est plus un spinner infini : l'état du réseau remonte du port jusqu'aux écrans, qui disent « hors connexion ».

Le budget LCP n'est pas tenu, et le maquiller n'aurait servi à rien

4 610 ms mesurés contre 2 500 visés — mais 192 ms sans bridage : l'écart est du transfert, pas du calcul. 641 Ko compressés à 200 Ko/s font 3,2 s à eux seuls, dont 495 Ko de plancher de pile — Reanimated, gesture-handler, react-native-svg et FlashList, imposés par le cahier des charges lui-même. Une coque vide dépasserait déjà le budget.

C'est pourquoi le budget de bundle porte sur le poids ajouté par le code applicatif : c'est le seul chiffre qui mesure une dérive. Les leviers qui restent — HTTP/2, Brotli, un CDN — sont hors du code.

La suite de bout en bout tourne contre l'export de production, sans back-end. Au premier passage elle a trouvé six vrais défauts — un autocomplete invalide, l'absence de lang="fr", des pages sans titre, une erreur React sur une route inconnue. C'est tout l'intérêt de la faire tourner sur ce qui est livré plutôt que sur ce qui est développé.

L'honnêteté du bilan

Ce qui reste dû avant une mise en ligne

Certaines exigences ne se simulent pas. Elles sont écrites ici plutôt que passées sous silence :

  • une passe manuelle VoiceOver / TalkBack, rideau d'écran activé, sur le chemin critique — les outils automatiques couvrent environ un tiers des critères ;
  • la fluidité au profileur, fil JS chargé, pendant qu'une course tourne et qu'un flux arrive à la seconde ;
  • l'enregistreur sur un appareil réel : service de premier plan tenu trois heures, relance après un kill, batterie sur une heure de course ;
  • les parcours Maestro, écrits mais jamais exécutés — ils demandent un dev build, les modules natifs étant absents d'Expo Go ;
  • un fournisseur de tuiles : la carte pointe encore sur le style de démonstration de MapLibre ;
  • côté back-end, un endpoint qui résout un identifiant de compte en profil — sans lui, les abonnés et les auteurs de commentaires ne peuvent pas être nommés.
